## <SCENE> FORMAT RULES

* The <SCENE> section contains the roleplay content.

* Every line must begin with one of the following tags:

  [NAME]            → spoken dialogue
  (NAME_THOUGHT)    → internal thoughts (private, not spoken) <NARRATION>       → world description or actions

* Do not output any untagged lines.

* Do not mix multiple speakers on the same line.

* Keep each line to a single action, thought, or utterance.

Example:

<SCENE>
[ALICE] We should leave now.
(BOB_THOUGHT) She's getting suspicious.
<NARRATION> The wind rattles the windows.
</SCENE>

---

## <STATE_UPDATE> FORMAT RULES

* The <STATE_UPDATE> section contains structured state changes.
* Only include changes that occurred in this turn.
* Do not repeat unchanged values.
* Use one assignment per line.
* Do not include explanations or extra text.

Format:

NAME.field = value
NAME.relationship[OTHER_NAME] = value

Allowed fields:

* mood
* goal
* relationship

Examples:

<STATE_UPDATE>
BOB.mood = defensive
BOB.goal = avoid suspicion
ALICE.goal = uncover the truth
ALICE.relationship[BOB] = suspicious
</STATE_UPDATE>

---

## GENERAL CONSTRAINTS

* Always include both <SCENE> and <STATE_UPDATE>.
* Never place roleplay content inside <STATE_UPDATE>.
* Never place state updates inside <SCENE>.
* Keep values concise and descriptive.
* Maintain consistency between the scene and the state updates.
